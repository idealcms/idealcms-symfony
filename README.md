# Подключение Ideal CMS

1. Устанавливаем symfony-проект.
2. Настраиваем подключение к БД. 
3. Через composer добавляем бандл idealcms/idealcms.

# Минимальная настройка

1. Нужно создать классы сущностей, которые будут использоваться в вашем проекте. Как минимум нужно создать класс `Part`, унаследовав его от `AbstractPart`.

# Расширение функциональности.

## Расширение функциональности моделей

Эта возможность встроена по-умолчанию, так как все сущности в бандле IdealCms абстрактные и для
использования их в своём проекте, обязательно нужно создать наследника от абстрактной сущности
и этого наследника уже можно кастомизировать по своему усмотрению.

## Расширение функциональности репозиториев

Создаём репозиторий нужной сущности, унаследовав его от репозитория этой сущности из бандла. Например:

```php
namespace App\Repository;

use IdealCms\Structure\Part\Repository\PartRepository as AbstractPartRepository;

class PartRepository extends AbstractPartRepository
```
И указать созданный репозиторий в атрибутах класса сущности.

```php
use IdealCms\Structure\Part\Entity\PartAbstract;
use App\Repository\PartRepository;

#[ORM\Entity(repositoryClass: PartRepository::class)]
class Part extends PartAbstract
```

## Расширение функциональности контроллеров

В каждой сущности есть метод getController(), который можно переопределить в своём приложении
и возвращать любой класс, как отнаследованный от исходного контроллера сущности, так и от
AbstractController. Во втором случае вы можете не только изменить функциональность методов,
или добавить новые, но и изменить список параметров у стандартных методов (index() и detail()).

## Расширение функциональности роутеров

Каждой сущности соответствует свой роутер, который, на основе url, строит путь по данным 
из таблицы сущности и определяет вызываемый action (то есть метод контроллера).
Если необходимо его переопределить в проекте, то нужно создать соответствующий класс
и вернуть его в методе getRouter соответствующей сущности.
